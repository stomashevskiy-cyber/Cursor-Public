# Аудит VBA-модуля SAP Scripting: `m_ZFI_TX04_008_AI_Changes`

## 1. Что в архиве

Архив `OKComputer_ZFI________bdae.zip` содержит **один файл** — стандартный модуль VBA `m_ZFI_TX04_008_AI_Changes.bas` (1880 строк, кодировка cp1251, CRLF, версия 1.42). Распакован в `internal/vba-sap/` без изменений (побайтно сверен с архивом).

Что делает модуль: макрос `PDChange` читает параметры с листа «Итоговый отчет» (вариант, год, период, версии B4/C4, шаги B5/C5), через SAP GUI Scripting открывает SE16N, выгружает таблицу `ZFI_TX04_008_AI` в буфер обмена (~340 тыс. строк, ~41 колонка, 100+ МБ текста), разбирает её в массив, пишет на лист данных и выполняет три блока проверок по ТЗ (качество данных в версии, сверка версий, консистентность шагов). Результат — таблица ошибок на листе отчёта.

Зависимость, которой **нет в архиве**: модуль `m_sapGui` (`SAP_Connection`, `OpenTransaction`). Подключение к SAP и работа с учётными данными в нём не аудировались.

## 2. Краткий вывод

- Модуль уже заметно оптимизирован по истории правок (1.16–1.41: кэш ключей, одна запись массива на лист, пересоздание листа, фиксированные ширины вместо AutoFit). Базовые приёмы Excel (`ScreenUpdating`, `Calculation`, `EnableEvents`, запись массивом, словари) соблюдены.
- **Хардкода логинов, паролей, хостов, `Shell`, сетевых вызовов в модуле нет.** Риск по безопасности — не в коде, а в данных (см. п. 3.9) и в неаудированном `m_sapGui`.
- Остаются резервы в четырёх местах: (1) пик памяти и объём копий строки 100+ МБ; (2) вывод таблицы ошибок (`Hyperlinks.Add` и поячеечная запись); (3) ожидания (холостой цикл `DoEvents`, `Timer` через полночь); (4) надёжность — деструктивные действия до подключения к SAP, нет проверки сессии/статус-строки, зависимость разбора чисел и дат от региональных настроек, тихая потеря строк.
- Подготовлена улучшенная версия `optimized/m_ZFI_TX04_008_AI_Changes.bas` (v2.00, 1516 строк). Логика проверок и макет отчёта сохранены. **Версия не компилировалась и не запускалась** — в среде нет Excel и SAP. Выполнена только статическая проверка парности блоков и ручное ревью, поэтому перед внедрением нужен прогон (раздел 7).

### P3 — читаемость, мелочи

- **3.15 Парсинг (стр. 1556–1580):** на каждую из ~338 тыс. строк делается `Replace(line,"|","")` (копия строки ~300 симв.), повторный `Trim(clipLines(headerLineIdx))`, `Trim(CStr(parts(c)))` дважды для сумм, `Split` в `Variant`. **[сделано]**
- **3.16 Структура:** `PDChange` — ~700 строк (1183–1880) и ~70 локальных переменных; 200 строк истории правок в шапке модуля; ASCII-схема с символами `¦ ¬ L` (испорчены кодировкой); непоследовательные комментарии. **[сделано]** — процедура разбита на `ReadParams`, `PrepareSheets`, `ExportSe16nToBuffer`, `ParseExport`, `ResolveColumns`, `BuildRowCache`, `WriteDataSheet`, `Check1/2/3`; параметры и колонки — в структурах `TRunParams`/`TCols`. История правок лучше хранить в системе контроля версий.
- **3.17 Мёртвый код:** `ActivateSAP` (не вызывается), константа `SAP_OKCD`, `Collection`-сборка из фрагментов (выгрузка всегда один фрагмент), `headerKey`, `m_dictStepIdx` (глобальная переменная ради одного цикла), неиспользуемые параметры `Check1/2/3` (`arrData`, `idxVERS`, `idxSTEP`, `idxSPP`, `idxSumNDD`, `idxSumBE`, `idxDatePay`). **[сделано]**
- **3.18 `FindWindow(..., Application.Caption)`** — ненадёжно (заголовок меняется); заменено на `Application.Hwnd`. **[сделано]**
- **3.19 Типизация значений на листе данных:** `Range.Value = массив строк` позволяет Excel «угадывать» тип. Текстовые колонки вида «0100123» теряют ведущие нули, а текст, похожий на дату, становится датой. Дриллдаун из отчёта на такие строки остаётся верным, но сравнение с SAP «глазами» — нет. **[рекомендация]** — выставить `NumberFormat="@"` для нечисловых колонок до записи (стоит памяти и меняет поведение фильтров по датам, поэтому решение за владельцем).
- **3.20 Колонка D отчёта** (СПП или сцепка документа) могла превратиться в число/дату (например «1-2»). **[сделано]** — формат «@» перед записью.

## 4. Конкретные улучшения: до / после

### 4.1 Ожидание буфера: холостой цикл и полночь (3.3, 3.4)

До:

```vba
clipTimeout = Timer + timeoutSec
...
nextPoll = Timer + 0.5
Do While Timer < nextPoll
    DoEvents
Loop
Loop While Timer < clipTimeout
```

После:

```vba
Private Function ElapsedSec(ByVal t0 As Double) As Double
    Dim d As Double
    d = Timer - t0
    If d < 0 Then d = d + 86400#      ' переход через полночь
    ElapsedSec = d
End Function

Private Sub PauseMs(ByVal ms As Long)
    Sleep ms                          ' kernel32, не нагружает процессор
    DoEvents
End Sub
...
If Len(bufferText) > 1 Then PauseMs 500 Else PauseMs 250
Loop While ElapsedSec(t0) < timeoutSec
```

### 4.2 Вывод таблицы ошибок: буфер + формула вместо `Hyperlinks.Add` (3.2)

До (на каждую строку ошибки):

```vba
wsReport.Cells(resRow, 1).Value = blockName
' ... ещё 8 обращений к Cells ...
wsReport.Hyperlinks.Add Anchor:=wsReport.Cells(resRow, 5), Address:="", _
    SubAddress:="'" & m_wsData.Name & "'!A" & CStr(rowNum), TextToDisplay:=CStr(rowNum)
wsReport.Cells(resRow, 6).NumberFormat = "#,##0.00"
```

После (строки копятся в `m_eb`, сброс на лист каждые 2000 строк):

```vba
m_eb(n, 6) = CDbl(valCur)                               ' число / дата
m_ebLink(n, 1) = "=HYPERLINK(""#'" & m_wsData.Name & "'!A" & rowNum & """," & rowNum & ")"
...
.Cells(m_ebFirstRow, 1).Resize(n, ERR_COLS).Value = tmp   ' одно присваивание
.Cells(m_ebFirstRow, 5).Resize(n, 1).Formula = tmpLink    ' дриллдаун
ApplyKindFormat runStart, r - 1                           ' формат по сериям строк
```

Внешне — тот же дриллдаун (синий подчёркнутый номер строки), без `Hyperlinks.Add`.

### 4.3 Итоги по группам: индексы вместо `Dictionary` + `Array()` (3.6)

До (Блок 1, на каждую строку версии):

```vba
If dictSum.Exists(spp) Then
    v = dictSum(spp)
    dictSum(spp) = Array(v(0) + m_arrSumM(i), v(1) + m_arrSumN(i), v(2))
Else
    dictSum.Add spp, Array(m_arrSumM(i), m_arrSumN(i), i + 1)
End If
```

После: номер группы вычисляется один раз при построении кэша (`m_arrGrp(i)`), в проверках — арифметика над типизированными массивами:

```vba
g = m_arrGrp(i)
If firstRow(g) = 0 Then
    firstRow(g) = i + 1: nSum = nSum + 1: ordSum(nSum) = g   ' порядок первого появления сохранён
End If
sumM(g) = sumM(g) + m_arrSumM(i)
sumN(g) = sumN(g) + m_arrSumN(i)
```

Одна и та же нумерация групп используется в Блоках 1, 2 и 3 (раньше ключ повторно искался в разных словарях).

### 4.4 Разбор чисел, дат, ключей без зависимости от локали (3.7)

До:

```vba
ParseSapNumber = CDbl(cleanSumStr)                 ' "1234,56" зависит от Windows
If dtPay < CDate(DATE_THRESHOLD) Then               ' "01.01.2025" зависит от Windows
t = CStr(CLng(t))                                   ' "1,5" -> 2; >2^31 не нормализуется
```

После:

```vba
t = Replace(t, ",", ".")
ParseSapNumber = Val(t)                             ' Val всегда читает точку
If s Like "##.##.####" Then dt = DateSerial(y, m, d)
m_dtThreshold = DateSerial(2025, 1, 1)
If Not (t Like "*[!0-9]*") Then ... убрать ведущие нули строковыми операциями
```

Допущение формата SAP (точка — разделитель тысяч, запятая — десятичная) сохранено. Если у пользователя SAP другая десятичная нотация, суммы разойдутся (в оригинале так же). Рекомендуется закрепить нотацию в профиле или проверять ее.

### 4.5 Парсинг и потеря строк с «---» (3.10, 3.15)

До:

```vba
line = Trim(clipLines(i))
If InStr(line, "|") > 0 And InStr(line, "---") = 0 Then
    If Replace(line, "|", "") <> "" And line <> Trim(clipLines(headerLineIdx)) Then
        parts = Split(line, "|")          ' Variant
        ... arrChunk(dataRowIdx, c) = Trim(CStr(parts(c)))   ' даже для пустых
```

После:

```vba
hdrLine = Trim$(clipLines(headerIdx))                 ' один раз
Private Function IsSeparatorLine(ByRef ln As String) As Boolean
    If InStr(ln, "---") = 0 Then Exit Function
    IsSeparatorLine = (Len(Replace(Replace(ln, "-", ""), "|", "")) = 0)   ' только «-» и «|»
End Function
...
parts = Split(ln, "|")                                ' String()
s = Trim$(parts(c))
If Len(s) > 0 Then nonEmpty = True: arrOut(tgt, c) = ...   ' пустые ячейки не пишем
```

До: очистка/удаление листа → подключение к SAP; восстановление Excel — три копии кода; `ErrorHandler` не освобождает кэши.

После:

```vba

...
Set sess = SAP_Connection()
If sess Is Nothing Then Fail "Не удалось подключиться к SAP ..."
```

### 4.7 Надёжность SAP-вызовов (3.8)

До: `.findById(path).Text = v` — при отсутствии элемента ошибка без пути.

После:

```vba
Private Function SapEl(ByVal sess As Object, ByVal id As String) As Object
    Set el = sess.findById(id, False)          ' Raise = False
    If el Is Nothing Then Fail "Элемент SAP GUI не найден: " & id & _
        ". ... Статус-строка SAP: " & SapStatusText(sess)
```

Плюс `SapWaitReady` (проверка `Busy` с таймаутом) и `SapCheckStatus` (тип сообщения E/A после загрузки варианта и `Execute`).

### 4.8 Рекомендации, не внесённые в `optimized/`

**3.1а. Экспорт в файл вместо буфера обмена + потоковое чтение.** Самый крупный резерв по памяти (до ~400 МБ пика на 338 тыс. строк) и по надёжности (буфер обмена занят RDP/Win+V; «призрак» прошлого прогона; опрос 100+ МБ через `GetText`). Идея: в диалоге экспорта ALV выбрать «Локальный файл» (тот же формат, что у буфера, — проверить), указать `DY_PATH`/`DY_FILENAME` (временная папка пользователя), ждать появления файла и **стабильного размера** (`FileLen` — дёшево), читать `Open … For Input` / `Line Input` построчно и сразу складывать в массивы. Нужны запись скрипта на вашем SAP и проверка формата: внутри диалога экспорта имена элементов зависят от версии SAP GUI.

**3.8а. Сверка полей выбора по имени.** Индексы `[2,2]…[2,8]` стоит заменить поиском строки таблицы выбора по имени поля (`GJAHR`, `MONAT`, `VERS`, `STEP`) либо добавить сверку имени поля в строке перед записью. Идентификаторы колонок «имя поля» в `tblSAPLSE16NSELFIELDS_TC` нужно взять из записи скрипта SAP GUI.

**3.19. Типы значений на листе данных** — см. выше.

**Безопасность подключения.** Проверить модуль `m_sapGui`: подключение должно брать уже открытую сессию (`GetObject("SAPGUI")` → `Children(0).Children(0)`) или запускаться через SAP Logon Pad с SSO/SNC. Любые логин/пароль в коде, листе или `Environ` — убрать, хранить в Windows Credential Manager или не хранить вообще. В `m_ZFI_TX04_008_AI_Changes` их нет (проверен поиск по `password/пароль/логин/login/user/http/Shell/Environ`).

## 5. Ожидаемый эффект

Замеров на живом SAP/Excel нет, поэтому ниже — оценка по числу операций, а не измеренные значения. Базовые данные — цифры из истории самого модуля (340 тыс. строк, экспорт SAP ~180–190 сек, 14 млн ячеек в массиве).

| Изменение | Ожидаемый эффект |
|---|---|
| Время ожидания SAP-экспорта (~3 мин) | не меняется — это время SAP; но Excel перестаёт занимать ядро процессора (Sleep вместо спин-цикла), что может немного ускорить саму выгрузку, если SAP и Excel на одной машине |
| `Hyperlinks.Add` + поячеечная запись (3.2) | при 1–10 тыс. ошибок: с десятков секунд (оценка 3–10 мс на гиперссылку и ещё столько же на остальные ячейки строки) до **<1–2 сек** на сброс; при 0 ошибок эффекта нет |
| Словари с `Array()` (3.6) | Блоки 1–3: порядка 10⁶ операций словаря и аллокаций на блок; ожидаемо в **2–4 раза быстрее** (секунды → доли секунды на блок) |
| Парсинг (3.15) | ~5–15% времени этапа парсинга (затрагивает 338 тыс. строк × `Replace`/`Trim`); основное время — `Split` и присваивания, они остаются |
| Дамп буфера выключен (3.9) | минус запись 338 тыс. строк на лист (**несколько секунд**) и **~100–200 МБ** памяти/размера файла; можно включить флагом |
| Потеря данных/неверные числа (3.7, 3.10, 3.13) | не скорость, а **корректность**: устраняет тихие ошибки при смене региональных настроек, строках с «---», периодах 13–16 |
| Надёжность (3.4, 3.5, 3.8, 3.11, 3.12, 3.14) | исключает зависание в районе полуночи, потерю старого отчёта при недоступном SAP, ошибку «91» без указания элемента, запись в чужую книгу, падение на 1M+ строк |
| Потоковый экспорт в файл (3.1а, не внесено) | пик памяти **−~400 МБ**, ушли бы «Out of string space» и зависимость от буфера обмена; реальный выигрыш по времени — после замера |

## 6. Что изменилось в `optimized/` (и что нет)

- Не менялось: тексты и условия проверок, порядок и состав колонок отчёта, формат ключа при флажке «Документ СПП», пороги и допуски, проценты прогресса, порядок вывода ошибок (порядок первого появления сохранён).
- Явные отличия поведения: (а) дамп на «Технический лист» по умолчанию выключен (`SAVE_RAW_DUMP`); (б) дриллдаун — формула `HYPERLINK`, а не объект гиперссылки; (в) без листа «Итоговый отчет» в активной книге макрос останавливается с сообщением (раньше создавал пустой лист); (г) параметры B2/B3 валидируются (год — 4 цифры, период 1–16); (д) строки, содержащие «---» в данных, сохраняются; (е) `Check1/2/3` и `WriteErrTableRow` изменили сигнатуры (внутренние `Private`).
- Зависимости `SAP_Connection` и `OpenTransaction` остались внешними: сигнатуры не менялись.

## 8. Две версии модуля: `v_buffer` и `v_file` (v2.10) с замерами

На основе `optimized/m_ZFI_TX04_008_AI_Changes.bas` (v2.00) сделаны две самодостаточные версии. Проверки (Блоки 1–3), кэш, макет отчёта, запись на лист данных и обработка ошибок **байт-в-байт одинаковы** (процедуры `Check1/2/3`, `AddErrRow`, `BuildRowCache` и др. сверены `diff`-ом). Отличается только способ получения данных из SAP.

| | `v_buffer.bas` | `v_file.bas` |
|---|---|---|
| Имя модуля (VB_Name) | `m_ZFI_TX04_008_AI_Buffer` | `m_ZFI_TX04_008_AI_File` |
| Точка входа | `PDChange_Buffer` | `PDChange_File` |
| Экспорт ALV | в буфер обмена (радиокнопка `[4,0]`, как в оригинале) | в локальный файл (радиокнопка `[0,0]` «Unconverted») |
| Ожидание | текст буфера перестал расти, 3 опроса подряд | размер файла > 0 и неизменен 3 опроса подряд, затем файл открывается эксклюзивно (SAP закрыл запись) |
| Чтение | `GetText` → `Split` → разбор | заголовок построчно; копия файла в `%TEMP%\ZFI_TX04_008_AI_ado\import.txt` + `schema.ini`; ADODB (ACE 16 → ACE 12 → Jet 4.0 → ODBC Access Text Driver), `SELECT * FROM [import.txt]`, порции `GetRows` по 20 000 строк |
| Запасной путь | — | если ADO нет или вернул не то число строк (`rowCount` SAP) — построчно `Line Input` (для UTF-8 — `ADODB.Stream`) |
| Память | строка 100+ МБ и массив строк | строка не создаётся; пик — массив данных плюс порция 20 000 строк |
| Файлы на диске | нет | файл выгрузки и рабочие файлы удаляются после чтения (`KEEP_EXPORT_FILES`); при ошибке остаются, путь — в сообщении |

Модули можно держать в книге одновременно: процедуры `Private`, имена точек входа и модулей разные, листы отчёта/данных и таблица замеров общие. Кнопке нужно назначить `PDChange_Buffer` или `PDChange_File` (или завести в старом модуле тонкую обёртку `Public Sub PDChange(): PDChange_File: End Sub`).

### 8.1. Как запускать

1. Скопировать книгу. Импортировать нужные модули: VBE → File → Import File → `v_buffer.bas` и/или `v_file.bas`. Старый модуль можно оставить — конфликтов имён нет, но его `PDChange` лучше не использовать вместе с новыми.
2. Должен остаться модуль `m_sapGui` (`SAP_Connection`, `OpenTransaction`).
3. Debug → Compile VBAProject. Это обязательный шаг: модули не компилировались (нет Excel).
4. Назначить макрос кнопке или запустить из Alt+F8: `PDChange_Buffer` / `PDChange_File`. Параметры — те же ячейки листа «Итоговый отчет» (B1:C5) и флажок «Документ СПП».
5. Для сравнения версий запускать обе на **одинаковых параметрах**, лучше по два раза подряд (первый прогон «холодный»: файловый кэш Windows, SAP-буферы), и в разное время суток не смешивать.
6. Настройки версии `file` — блок констант «Версия «файл»» в начале модуля (см. 8.4).

### 8.2. Как читать замеры

Таблица пишется на лист «Технический лист» **без стирания истории** (стирается только колонки A:D; раньше очищался весь лист).

- **Колонки F:N — этапы, 13 строк на прогон:** «Прогон №» (сквозной для обеих версий), «Версия» (`buffer`/`file`), «Запуск» (дата и время), «Этап», «Начало этапа» (время суток первого старта), «Длительность, сек», «% от общего», «Строк в выгрузке», «Примечание» (в строке «ИТОГО»: OK/ОШИБКА, версии, шаги, период, режим чтения файла).
- **Колонки P:AG — сводка, одна строка на прогон:** номер, версия, запуск, число строк, затем длительности по 13 этапам и результат. Здесь удобно фильтровать по версии и сравнивать.
- Этапы: 1 подключение к SAP; 2 подготовка листов; 3 SE16N — условия выборки и запуск (до появления грида с `rowCount`); 4 ожидание/формирование экспорта (от команды экспорта до готовности данных: для буфера — стабильный размер буфера, для файла — диалог сохранения и стабильный файл); 5 получение данных (buffer: чтение буфера, разбиение на строки, заголовок; file: заголовок, копия файла, открытие ADO); 6 разбор в массив; 7 кэш ключей; 8 запись на лист данных; 9–11 Блоки 1–3 (для двух версий SAP-версий — сумма вызовов); 12 вывод отчёта; 13 итого.
- **Время записи таблицы ошибок внутри блоков вынесено из Блоков 1–3 в этап 12** (иначе блоки с большим числом ошибок выглядели бы дороже, чем их расчёт). Сумма этапов 1–12 почти равна «ИТОГО»; разница — служебные операции между этапами (чтение параметров, прогресс, финальная очистка).
- Время — `QueryPerformanceCounter` (монотонный счётчик, не зависит от полуночи); если API недоступен, используется `Timer` с поправкой на обнуление.
- При ошибке замеры тоже пишутся (результат «ОШИБКА», в примечании — текст и этап), поэтому «ИТОГО» неудачного прогона нельзя сравнивать с успешным.
- Что сравнивать между версиями: этапы 4–6 (экспорт → данные → разбор) и пик памяти (Диспетчер задач, `EXCEL.EXE`). Этапы 1–3 и 7–12 должны совпадать с точностью до шума.

### 8.3. Совпадение результатов

Результат версий должен совпадать построчно: листы «Итоговый отчет» и «ZFI_TX04_008_AI». Проверка: запустить обе версии, затем сравнить листы (например, `=EXACT()` по диапазону или экспортом в текст и `fc`). Источники возможных расхождений при чтении из файла: кодировка (кириллица в заголовке и текстовых полях), кавычка `"` в начале значения (текстовый драйвер считает её ограничителем текста), строки данных, содержащие `---` (обрабатываются одинаково в обеих версиях). Контроль: при `ADO_VERIFY_ROWCOUNT = True` число строк ADO сравнивается с `rowCount` грида SAP; при расхождении выполняется построчное чтение, режим фиксируется в примечании «ИТОГО».

### 8.4. Настройки версии `file`

| Константа | По умолчанию | Назначение |
|---|---|---|
| `EXPORT_DIR_OVERRIDE`, `EXPORT_FILE_OVERRIDE` | `""` | пусто — берётся каталог и имя, которые SAP предлагает в диалоге сохранения; иначе — свои |
| `EXPORT_DIR_FALLBACK` | `\Documents\SAP\SAP GUI\` | от `%USERPROFILE%`, если SAP ничего не предложил |
| `EXPORT_NAME_FALLBACK` | `export.txt` | если и имя не предложено |
| `EXPORT_NAME_STAMP` | `False` | добавлять метку времени к имени (защита от блокировки старого файла) |
| `EXPORT_ENCODING_SAP` | `""` | не менять кодировку в диалоге; `"4110"` — UTF-8 |
| `FILE_CHARSET` | `ANSI` | кодировка чтения: `ANSI`, `OEM`, `UTF-8`; должна соответствовать выгрузке |
| `FILE_READ_MODE` | `ADO` | `ADO` или `LINES` (только построчно, без драйверов) |
| `FILE_WAIT_SEC`, `FILE_POLL_MS`, `FILE_STABLE_TICKS` | 900 / 500 / 3 | ожидание файла |
| `ADO_CHUNK_ROWS` | 20000 | размер порции `GetRows` |

### 8.5. Ограничения и что проверить на реальном SAP

Ни один из модулей не компилировался и не запускался. Выполнена статическая проверка: парность `If/For/Do/With/Select/Sub/Function/Type`, отсутствие необъявленных идентификаторов при `Option Explicit` (по процедурам), отсутствие дублей объявлений, лимиты строк и продолжений, кодировка cp1251 + CRLF. Типичные ошибки, которые может поймать только компилятор Excel: несовпадение типов в вызовах, свойства объектов COM.

**Имена полей диалога экспорта — проверить записью скрипта** (SAP GUI: Alt+F12 → Script Recording and Playback; выполнить вручную: ALV → Экспорт → «Локальный файл…» → формат → сохранить), и при отличиях поправить константы в начале `v_file.bas`:

- `SAP_EXPORT_DLG_FLAG_FILE` = `wnd[1]/usr/subSUBSCREEN_STEPLOOP:SAPLSPO5:0150/sub:SAPLSPO5:0150/radSPOPLI-SELFLAG[0,0]` — формат «Unconverted». В `v_buffer` та же группа радиокнопок с индексом `[4,0]` (буфер). Допущение: порядок «Unconverted, Spreadsheet, Rich text, HTML, In the clipboard»; в другом порядке индекс `[0,0]` надо заменить на нужный.
- `SAP_FILE_DLG_PATH` = `wnd[1]/usr/ctxtDY_PATH`, `SAP_FILE_DLG_NAME` = `wnd[1]/usr/ctxtDY_FILENAME`, `SAP_FILE_DLG_ENCODING` = `wnd[1]/usr/ctxtDY_FILE_ENCODING` (поле кодировки необязательное: ошибка при его отсутствии игнорируется), `SAP_FILE_DLG_OK` = `wnd[1]/tbar[0]/btn[0]` (в разных версиях кнопка может быть `btn[11]`).
- **Формат файла «Unconverted» должен совпадать с форматом буфера**: строки с `|`, строка заголовка с «СПП»/«Версия», разделители из дефисов. Если у вас формат иной (табуляция, другой порядок строк) — парсер заголовка `FindHeaderInFile` и schema.ini нужно менять.
- Совпадение выгрузки: сравнить число строк и контрольные суммы M и N между версиями.

Другие ограничения версии `file`:

- Файловый доступ из SAP GUI может быть заблокирован политикой: диалог «SAP GUI Security» (запрос доступа к файлам) нельзя нажать скриптом, и прогон ждёт таймаут `FILE_WAIT_SEC`. Решение — правило «разрешать» для каталога экспорта в настройках безопасности SAP GUI. Сообщение о таймауте на это указывает.
- ADO: нужен провайдер **той же разрядности, что и Office** (ACE OLEDB 12/16 входит в Office/Access Runtime; Jet 4.0 — только 32-бит). Если подходящего нет, модуль переходит на построчное чтение и записывает причину в примечание; прирост по памяти сохраняется, прирост по времени — нет.
- `schema.ini` создаётся в `%TEMP%\ZFI_TX04_008_AI_ado\` (чужие `schema.ini` не затрагиваются); значения ограничены 255 символами на ячейку, значение, начинающееся с `"`, может быть интерпретировано драйвером как ограничитель.
- UTF-8: построчное чтение идёт через `ADODB.Stream.LoadFromFile`, то есть читает файл целиком в память COM (сырые байты, без 100+ МБ VBA-строки); `LineSeparator` — CRLF.
- Права: запись в каталог экспорта, который предлагает SAP, и в `%TEMP%`.
- Рабочая книга должна быть активной и содержать лист «Итоговый отчет».
- Без реального прогона оценка выигрыша версии `file` по времени остаётся гипотезой: экспорт SAP в файл и в буфер может занимать разное время, а ADO добавляет копирование файла (~1–2 сек на 100 МБ). Главное ожидаемое преимущество — память и отсутствие зависимости от буфера обмена; решение «что быстрее» принимать по таблице замеров.
